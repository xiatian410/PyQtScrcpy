# 后续更新与优化方案

本方案以 2026-11-18 本地整合版为起点，按验收门槛推进，避免未经真机测试直接发布稳定版。

## P0：发布前验收（建议第 1 周）

1. 在 Windows 10、Windows 11、Linux X11/Wayland、macOS ARM 上运行 CI 和目录包。验收：冷启动、设备列表、拖动/缩放、语言切换、含中文路径、无工具时提示正常。
2. 建立 Android 11/12/14/15/16 真机矩阵，至少一台 Pixel/AOSP 和一台 HyperOS。验收：USB 投屏/控制、音视频录屏、无线首次配对/重连、APK 覆盖安装/签名冲突、摄像头/高速模式、虚拟显示与应用迁移。
3. 多设备并发、拔线、未授权、offline、ADB 服务重启、安装超时、关闭活跃投屏压力验证；重点关注运行中录屏的封装完整性。
4. 检查发布包所有动态库与 NOTICE、源代码提供义务；为产物生成 SHA-256、SBOM，记录构建系统和 Python/Qt 完整版本。
5. 发布 `2.0.0-rc1`，收集上述矩阵结果后再打稳定标签。当前版本仍为 `2.0.0-dev`。

## P1：连接和可维护性（建议第 2–3 周）

- 引入 `adb track-devices` 事件监听，减少手工刷新；设备变化防抖，保留显式 serial 隔离和过期结果丢弃。
- 增加 mDNS 服务发现、配对与连接分步操作、连接历史、重连和单设备断开；默认不记录配对码。
- 将 GUI 从 `main.py` 拆为设备控制器、会话控制器、设置页面、对话框和翻译目录；新设置集中建模。
- 增加可取消任务、单设备任务队列、每个会话独立日志与停止按钮；录像优先温和退出并验证文件可播放。
- 扩展能力检测：缓存 scrcpy 版本/帮助结果，以实际能力禁用不支持选项；Android 版本/编码器查询按设备缓存。
- 增加常见 ADB 错误的本地化解释，保留原始输出便于诊断。

验收：连续切换多设备无串机、网络中断可恢复、UI 响应不受查询影响、各模块可单独测试。

## P2：交互与性能（建议第 4–6 周）

- 重新布局高级面板，按屏幕/音频/录屏/连接分组，适配高 DPI 和小屏。
- 每设备配置档案、导入导出、只展示启用选项；Qt `.ts/.qm` 标准翻译工作流和更多语言。
- scrcpy 5.x 硬件解码、编码器、键鼠 UHID、手柄等新参数，按用户需求和设备能力分批暴露。
- 性能基线：首次启动、设备发现、投屏首帧、后台 CPU/内存、切换配置耗时；先测量再优化。
- 按键映射作为独立可选功能评估，明确 Android 输入限制及与 UHID 的交互。

## 持续更新制度

| 周期/触发 | 动作 | 合并条件 |
| --- | --- | --- |
| 每月 | Dependabot 检查 Python 与 Actions；人工查 scrcpy 和 Android 稳定通道 | PR 中记录版本差异、移除参数、最低系统要求 |
| scrcpy 稳定版发布 | 更新 `components.lock.json` 的整套官方包与 SHA-256；同步 Windows `bin/` | CLI 参数测试、三平台版本检查、至少 USB/录屏真机通过 |
| Platform-Tools 稳定版发布 | 从 Google stable/channel-0 获取固定版本包，核对官方 SHA-1 后生成 SHA-256 | USB、无线配对、多设备、安装 APK 回归通过 |
| Qt/Fluent 大版本 | 建独立升级分支，重生成 UI，核查信号与控件 API | 启动、语言切换、交互和打包测试通过 |
| 安全修复 | 优先评估受影响使用路径，必要时提前发补丁 | 相关回归 + 构建可复现证据 |

维护直接依赖的明确版本；平台依赖保持平台标记；发布前保存各平台完整解析结果。不要将一个平台的 `pip freeze` 直接覆盖所有平台的 requirements。

下载更新采用“检查 → 显示变更 → 校验下载 → 关闭会话 → 替换 → 自检”的流程；本次已实现命令行下载校验和上一版目录备份，未来 GUI 更新入口应沿用此机制。回退同时回退 scrcpy 可执行文件、server、DLL，禁止只替换一个文件。
